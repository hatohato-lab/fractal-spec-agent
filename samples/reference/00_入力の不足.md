# 入力の不足 — この設計書のもとになった入力の点検

上へ戻る: [00_枠](./00_枠.md)

入力（「AIが作る量と人間の認知が乖離している。設計書で埋めたい」）を8観点で点検した結果。
機械の点検は `python eval/oracle.py --gaps <入力ファイル>` で再現できる。

| 観点 | 状態 | 書かれていなければ聞くこと |
|---|---|---|
| 目的 | あり | — |
| 完了条件 | あり（オラクルPASS＋生成試験） | — |
| 前提 | **見当たらない** | 読者がMarkdownとMermaidを読める前提でよいか（要確認） |
| 制約 | **見当たらない** | 期限・使える時間の上限はどこか |
| 現状 | あり（既存の設計書は平らな1階層） | — |
| 関係者 | **見当たらない** | この設計書を読むのは誰か。誰が承認するか |
| 代替案 | あり（普通の設計書・スライド） | — |
| 失敗時 | **見当たらない** | 構造が守られても内容が伝わらなかった場合どうするか |

## 読み方

★の代わりに太字で示したものが、入力に書かれていなかった観点。

「前提」は重大な観点で、崩れると設計書全体が作り直しになる。
ここが埋まっていない状態で本体を書き進めた、という記録がこの1枚。

## この機能の位置づけ

不足を**埋めるのはこの機能の仕事ではない**。何が無いかを示すところまで。
埋める内容を勝手に作ると、確認されていない前提が本文に紛れ込むため。
